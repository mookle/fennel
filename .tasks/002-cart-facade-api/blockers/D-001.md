# D-001 · raised by developer · 2026-11-17

Question: `redocly lint --extends=minimal` warns that the three operations in `contracts/cart.openapi.yaml` have no `operationId`, and `contracts/product.openapi.yaml` breaks the same rule on all 11 of its operations, so should the cart contract add `operationId`s or follow product and leave them out?
Options: (a) leave them out, matching product; lint exits 0 with 3 warnings (the current state). (b) add `operationId`s to the three cart operations, which clears the warnings and makes cart diverge from product until product gains them too.
Recommendation: (a), because the task asks the contract to follow product's conventions and the warning does not fail the check; adding ids is a cross-contract convention for the user to set.
Evidence: `docker run --rm -v "$PWD/contracts:/spec:ro" redocly/cli lint --extends=minimal /spec/cart.openapi.yaml` reports "You have 3 warnings", all from the operation-operationId rule, and exits 0. The same command on product.openapi.yaml reports 11 operation-operationId warnings, 2 tag-description warnings, and 2 struct errors (product.openapi.yaml:374 a `description` with an unquoted comma, product.openapi.yaml:412 `nullable`, which OpenAPI 3.1 does not allow). The product errors are outside this task and noted for information only.
